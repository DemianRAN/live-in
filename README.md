# 関東ライブまとめ (live-in)

関東のライブハウス＋小ホールの公演情報を、各会場の**公式サイトだけ**から毎日自動収集して一覧表示する静的サイト。

- リポジトリ: DemianRAN/live-in
- 公開先（予定）: https://demianran.github.io/live-in/
- 更新: GitHub Actions で毎日 07:00 / 19:00 JST（1日2回）に収集 → data/ をコミット → サイト生成 → Pages へデプロイ

## ソース方針

- 収集元は会場の公式サイトのみ。チケットプラットフォーム（e+ / チケットぴあ / ローソンチケット等）は**収集対象にせず**、必要ならリンク先としてのみ扱う。
- 掲載するのは公演の事実情報（日付・開場/開演・タイトル・出演者・料金）と公式詳細ページへのリンクのみ。紹介文や画像は転載しない。
- 1会場の取得失敗で全体は止めない。失敗は `data/state.json` に記録される。

## 構成（fishing-catch プロジェクトと同型）

```
collector/
  venues.json   会場レジストリ（id・名前・都県・公式URL・スケジュールURL・アダプタ・状態）
  collect.py    収集（標準ライブラリのみ）→ data/events.json, data/state.json
  build.py      生成 → web/index.html（データ内包の単体HTML）, web/events.json
data/           収集結果（events.json / state.json）。リポジトリにコミットされる
web/            生成物（.gitignore 済み。Actions が Pages の artifact として公開する）
.github/workflows/
  collect.yml   毎日 07:00 / 19:00 JST に collect → data/ をコミット → build → Pages デプロイ（+ アラート検査）
  pages.yml     collector/ や data/ の手動変更を push したときに build → Pages デプロイ
```

## ローカル実行

```bash
python3 collector/collect.py   # 収集
python3 collector/build.py     # サイト生成
# web/index.html をブラウザで開く（「今日」は閲覧時の JST で判定される）
```

Python 3 の標準ライブラリのみで動作する（pip install 不要）。

## 収集アラート（失敗・件数減少の検知）

会場サイトの改版やブロックで収集が静かに壊れるのを防ぐため、`collect.py` は実行のたびに前回結果と比較してアラートを生成する。アラートは `data/state.json` の `alerts` 配列（`venue`, `venue_name`, `kind`, `prev`, `new`, `message`）に保存され、収集ログの末尾にも要約が出る。

- `fetch_failed`: 会場の取得が失敗した
- `zero_events`: 取得は成功扱いだが 0 件だった
- `count_drop`: 件数が前回比で 40% 超減少した（前回が 5 件未満の会場は対象外）

件数比較は **like-for-like**：前回の `events.json` から「今回の実行日以降の公演」だけを数え直し、今回分も同じ窓で数えて比べる。これにより、月替わりで前月分が一斉に失効しても（翌月分は前回ファイルにも含まれるため）誤報にならない。前回の `events.json` が読めない場合のみ state.json の生件数で代用する（その場合は message に明記される）。既知の限界：当月分しか載らない会場（MOSAiC 等、`venues.json` で `month_roll: true` の会場）は、月末が近づくと窓側の前回件数が小さくなり減少判定が自動的に外れるため、月替わり直後の減少は検出できない。部分的な警告（翌月ページ未公開など、件数が残っているもの）は単独ではアラートにしない（実害が出れば `count_drop` が拾う）。

各アラートには `streak`（同じ会場のアラートが何回連続しているか）が付く。GitHub Actions では、データのコミットとデプロイが済んだ**後**に `alerts` ジョブが走り、`streak` が `alert_fail_streak`（既定 2、`collect.py` の `ALERT_FAIL_STREAK`）以上のアラートがある場合だけワークフローを失敗させる（GitHub の失敗通知でオーナーに届く）。1回だけの一過性の取得失敗では通知しない。

### 前回公演の引き継ぎ（stale）

`fetch_failed` / `zero_events` / `count_drop` のアラートが出た会場は、収集側の不調でその会場の公演がサイトから消えないよう、前回の `events.json` から今日以降の公演を引き継ぐ（`count_drop` では今回取れた公演と同じものは引き継がない）。引き継いだ公演には `stale: true` と `stale_since`（引き継ぎ開始日）が付き、サイト上では「前回取得分・未更新」バッジが出る。引き継ぎは `stale_since` から最大 3 日（`CARRY_MAX_DAYS`）で打ち切る。引き継ぎ件数は各アラートの `carried` と state.json の `carried_events` に記録される。

### 時刻の正規化

`open` / `start` は `HH:MM`（0埋め、深夜表記は 29:59 まで）に正規化する。`TBA` など時刻でない値は時刻欄に入れず、`time_note`（例: `START TBA`）に回してサイトに表示する。

## 会場の追加方法

1. `collector/venues.json` に会場を追加する（`id`, `name`, `pref`, `area`, `site_url`, `schedule_url`, `adapter`, `status`, `note`）。
2. 既存アダプタで済む場合は `adapter` に既存の名前を指定する。新しいサイト構造の場合は `collector/collect.py` に `adapter_<name>` 関数を実装し、`ADAPTERS` に登録する。
   - アダプタは `(venue, fetcher)` を受け取り、`(events, errors)` を返す。`fetcher.fetch(url)` は `(ok, text_or_reason)` を返し、同一URLはキャッシュされる。
   - 日付は可能な限りページ側の明示情報（URLの YYYYMM、`data-event-date`、詳細URL末尾の日付）から確定すること。本文中の月日だけから推測する場合は「対象月 < 現在月なら翌年」のルールを明記する。
3. `python3 collector/collect.py` を実行し、`data/state.json` で対象会場が `ok` になり、件数と内容（タイトル・日付・曜日）が正しいことを確認する。
4. `python3 collector/build.py` でサイトを再生成する。

取得できない会場は無理にデータを捏造せず、`status: "pending"` と理由を `note` に書いて登録する。

## 状態マーク（完売・中止・延期）

- 各公演の `status` フィールドは、**その公演自身の一覧セグメント／公式詳細ページ本文**に明示された表現だけから判定する（ページ全体の告知からは付けない）。曖昧な場合は付けない。
  - `sold_out`: 「SOLD OUT」「完売」「売り切れ」「ソールドアウト」を含む（ただし「SOLD OUT 間近」「完売間近」は未完売として除外）
  - `cancelled`: 「開催中止」「公演中止」「中止となりました」等の明示
  - `postponed`: 「開催延期」「公演延期」「振替公演」等の明示
  - 付けない例：払い戻し・返金の定型注記中の「公演中止の場合」等の条件文、「完売の場合は当日券なし」等の条件文、配信だけの中止（会場公演は開催）、「内容を変更して開催」の公演、出演者一部のキャンセル。
- サイト上ではバッジ表示され、「完売・中止を隠す」チェックで完売・中止を非表示にできる。あくまで公式ページの表記時点の情報であり、最新の販売状況は公式ページで確認すること。なお券種限定の完売表記でも `sold_out` が付く場合がある。

## サイトの使い方・画面仕様

- **検索**：公演名・出演者・会場・エリアを対象に、全角/半角・大文字/小文字を区別せず検索する。スペース区切りで AND 検索。`/` キーで検索欄にフォーカス。
- **絞り込み**：期間（今日・明日・今後7日・今週末）、都県（件数付き）、会場（エリア別にまとめたプルダウン）、ジャンル、完売・中止を隠す。選択中のチップをもう一度押すと解除。カードの会場名を押すとその会場で絞り込む。
- **URL 共有**：絞り込み条件は URL のクエリ（`q` / `period` / `pref` / `venue` / `genre` / `hide`）に反映されるので、そのまま共有・ブックマークできる。例: `?period=weekend&pref=東京都`
- **スマホ**：幅 720px 未満では絞り込みを「絞り込み」ボタンで開くパネルにまとめ、検索バーを上部に固定する。日付見出しも検索バーの下に固定される。
- **表示件数**：一度に 120 件ずつ描画し、スクロールで続きを読み込む。
- **鮮度表示**：ヘッダーに最終更新からの経過時間を出し、26 時間以上更新が無い場合は注意書きを表示する。
- **ダークモード**：OS の設定（`prefers-color-scheme`）に追従する。

## カレンダー書き出し (.ics)

- 各公演カードの「カレンダーに追加」ボタンで、その公演1件の .ics をダウンロードできる（ブラウザ側で生成）。一覧上部のボタンでは、現在フィルタ中の公演をまとめて書き出せる。
- 時刻は JST の公演時刻を UTC に換算して出力する（`...Z` 形式。閲覧端末のタイムゾーンに関係なく正しい時刻になる）。開始は START（無ければ OPEN）、終了は開始＋2時間（公式に終了時刻の掲載がないため）。時刻が無い公演は終日イベントとして出力する。75 オクテットを超える行は RFC 5545 に従って折り返す。
- SUMMARY=公演タイトル、LOCATION=会場名（都県・エリア）、DESCRIPTION=出演・料金・公式URL、UID は会場ID＋日付＋タイトル等のハッシュで安定させる。中止公演には STATUS:CANCELLED を付ける。

## 備考

- PARKDINER の翌月分は、テーマ標準の AJAX エンドポイント（サイト自身の月送りが使うもの）で取得している。当月・翌月の2ヶ月分を掲載。
- 千葉 LOOK の翌月分は、公式の先取り情報ページ（schedule/new.html）から取得している。当月・翌月の2ヶ月分を掲載。なお LOOK は公式ページ自体が「CHARGE 未定」の公演があり、その場合は料金を空欄にしている。
- WWW / WWW X・HEAVEN'S ROCK 各店・CLUB CITTA' は一覧に料金が載っていないため、公式詳細ページから料金（と不足している開場/開演時刻）を補完している。詳細ページにも金額の記載がない公演（未定・後日発表など）は空欄のまま掲載する。
- `.github/workflows/` 配下のファイルは、環境によっては GitHub App の権限でプッシュできない場合がある（fishing-catch では手動追加が必要だった）。その場合は GitHub の Web UI から同内容で追加すること。
